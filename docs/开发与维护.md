# 开发与维护

面向维护者，汇总旧README中的技术与制作说明、开发计划和历轮维护入口。游戏介绍只放在[README](../README.md)；操作与发布见[游玩与部署](游玩与部署.md)，取材原则见[剧情与史料](剧情与史料.md)，历史阶段见[修订与验收](修订与验收.md)。

## 项目与目录

当前为独立游戏仓库，使用 React 19、TypeScript、Vite，纯前端运行。部署构建读取已生成剧情，不依赖原PDF、在线AI、账号或后端服务。Node版本、依赖和命令以[package.json](../package.json)与锁文件为准；CI使用Node 24。

| 位置 | 职责 |
| --- | --- |
| `src/main.tsx`、`src/style.css` | 播放器、手帐、首页、布局与演出 |
| `src/story.ts` | 组合剧情、日期、人物和背景，定义节点及状态推进 |
| `src/save.ts` | 自动／手动存档、校验、旧节点迁移、已读与收藏 |
| `src/reading.ts`、`src/cheat.ts` | 阅读设置、字素揭示与稳定混排；精确摘要校验 |

| `vercel.json`、`.github/workflows/deploy-pages.yml` | 两种部署入口 |

生成顺序为原资料及基础台本 → 审查补写、润色与二次补正 → 用户删改 → 121日扩增 → 稳定原节点ID → 新互动插入 → 旧档兼容及素材定位 → 输出。调整某一阶段前先读调用位置，不把多次补丁误当独立可乱序执行的生成器。

重新生成需要上级目录的 `人大附中2024届7班班史_全卷转写校勘.md`。它是取材依赖，不应为了让普通部署成功而复制私人原资料进仓库。基础日历现已独立成JSON，生成不再依赖维护文档的排版。

```sh
node scripts/produce-content.mjs
npm test
npm run build
node --experimental-strip-types scripts/delivery-report.ts
```

如需同步立绘，先检查同步脚本所需的图片源路径和清单，确认本地资源可用后执行；不要把文档中的历史归档路径当作每个克隆环境都有的目录。

## 稳定ID与存档

D／N日期ID和已发行节点ID不能因插入对白重新编号。`scripts/stable-nodes.mjs`与`review-node-ids.json`维护稳定登记；旧节点映射位于`legacy-nodes-v2.json`和`src/data/legacyNodes.ts`等兼容数据。新互动使用`interactive-原锚点ID`，新增成功回应拥有独立ID。

删除、挪日或改写节点时，同时处理当前画面、已读列表、历史记录及退役ID。c59合并为c38的迁移仍保留；九班徐子瀚不与徐子涵合并。旧存档版本1／2都须按已有解析规则验证，不因为旧已读列表含退役节点拒绝整份存档。

失败页是当前选择的临时结果，返回时恢复选择前应有状态，保留已读和收藏。成功回应分别演出后接回共同原节点。选项在界面按稳定ID混排；源数据的排列不等于屏幕顺序。

## 写作与验证流程

1. 读原事件及相邻段，登记人物、动作、时间、结果和用户确认；有关键疑读再回扫描。编排建议不是新史实。
2. 在真正维护源写起因、关键动作、来回回应、笑点和余波。选择写具体台词，玩家视角与当场知识一致，不借未来信息判错。
3. 标页码与原文／转述／补写。按需要添加回忆或作品标签，不让编剧约束混进对白。
4. 生成后通读事件及回扣，检查代词、参与者、道具、时序、未定日期和用户撤下要求。
5. 执行现有测试与构建，实际浏览器抽查修改段落、另一条成功回应、失败重选、刷新读取和手机长对白／选项。
6. 更新逐项台账及主题文档，记录确实执行的检查和没有检查的部分，不用节点数证明故事完成。

`?qa=1`仅在开发模式提供独立验收存档空间；抽查使用独立空间和游戏导入功能，不清空普通玩家记录。图片必须本地存在，背景或标题不能代替剧本，新增小游戏不属于本项目方向。

## 文档与报告维护

现在只有五份主题Markdown。不要再为每个小批次新增一份计划、进度、验收和交付声明；将规则更新到对应主题，在[修订与验收](修订与验收.md)追加简短批次记录。

[delivery-report.ts](../scripts/delivery-report.ts)现在只输出[当前版本结构统计](qa/当前版本结构统计.json)，包括实际日期／节点／选项数量、逐日分布、正常路线结局与旧整改锚点匹配情况，不覆盖人工主题文档，也不把旧浏览器证据包装成新验收。报告中的缺失历史锚点表示需要人工复核，并不自动证明该故事已删除或未完成。

旧[验收统计](qa/验收统计.json)与[本轮浏览器验收](qa/本轮浏览器验收.json)保留各自原批次身份。日常台账、互动节点对照和历史规划表是结构化证据，不直接当作当前完成声明。历史Markdown完整版本可从提交`50052ea`的`docs/`中读取。

## 工作区与提交

先检查Git状态并保护未提交工作。只提交游戏必要文件，生成数据和本地资源与修改源一起维护，不提交依赖目录、构建产物、敏感配置、原始照片及临时发布包。按用户授权决定是否提交或推送。

不执行sudo，不擅改全局配置。若确实需Python，先查项目指定conda环境，未指定则询问，不自行创建或猜测；普通剧情、文档和构建工作优先使用现有Node工具。

## 音乐准备室（试听阶段）

独立入口为 `/music-room/index.html`；页面使用相对资源路径，适应开发服务器和仓库子路径的静态部署。试听页不改变游戏存档；主播放器已按用户确认选曲接入BGM。当前准备15类配乐用途、19首完整音乐、5种翻页声、8段实际剧情试听，以及121日的场景用途建议；默认日常分类仍需在选曲后逐段细化，循环点尚未制作。

维护源是 `scripts/music/curation.json`，生成脚本是 `scripts/music/prepare-audition.mjs`。执行 `node --experimental-strip-types scripts/music/prepare-audition.mjs` 读取当前剧情、下载缺失素材、以ffprobe/ffmpeg检查解码并生成 `public/music-room/catalog.json` 和 `credits.txt`；需现有Node、curl、ffprobe、ffmpeg，游戏运行及普通构建无需这些音频工具。生成时按当前节点追踪一条成功回应用于独立试听摘录，不能将其当作新增主剧情。

音乐来自Kevin MacLeod官方曲库，授权CC BY 4.0；翻页声来自Freesound，四项CC0、一项CC BY 4.0。原作者、源页、授权、SHA256、采样率和文件大小保留在清单及页面署名层。这些是本地可授权素材候选，**不是七班原创音乐**；如最终采用原创配乐，本页用于确认风格。音效是公开HQ MP3试听文件而非原WAV。候选与正式播放共用 public/audio 文件，总音频约138 MiB，保留下载质量，不二次有损压缩，仅点试听才请求音频；主游戏只播放确认的11首配乐和S01，不预加载全套候选。

选曲仅写入独立键 `seven.music-review.v1`，支持刷新保留、复制文本与导出JSON选曲单。试听播放器可暂停、拖动进度、整曲循环，并分别调音乐／翻页音量。主旋律变奏、同曲连续与分通道规则的官方参考和本项目推论在试听页分别标注。

## 正式配乐接入（2026-10-07）

用户确认15类用途的候选曲，实际复用11首：Almost New、Autumn Day、Bossa Antigua、Investigations、Clean Soul、Fresh Air、Clear Air、Morning、Heartbreaking、Half Mystery、Inspired。翻页选S01（OwlStorm）。确认单在 `scripts/music/selection.json`；运行 `node scripts/music/install-selection.mjs` 校验原文件哈希，生成 `src/data/music.ts` 和正式署名文件。音频统一在 `public/audio/`，试听页引用同一文件，不重复保存选中曲。

`src/audio.ts` 根据当前节点／日期／场景标签选曲，同曲不重启，不因普通说话人变化、手帐或失败重选切歌。两个原生音频声道跨曲淡入淡出1秒，整曲循环；使用原文件，未宣称制作了无缝循环点。封面与毕业采用Almost New，人物页使用封面曲。切到后台暂停，回到页面续播；浏览器阻止自动播放时可点封面的“开启音乐”，开始或继续游戏的手势也会尝试开启。

设置保留旧文字／动画偏好；新增BGM默认35%、操作音效10%，原音效偏好作为真实翻页声的音量。翻日期自然进入新日、从封面重读首日，以及日期菜单切换到不同日期时播一次S01。同日对白、人物过场、失败重选、刷新及读档不补播。读档恢复场景对应曲目，未额外保存音乐播放秒数；同曲读档保持当前位置，刷新后从曲头开始。作品没有角色配音。
